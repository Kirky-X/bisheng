# narrative.md · 叙事与规划(动手前定结构)

> 结构错,后期翻修代价最高。本文件回答"这份 deck 讲什么、几页、每页什么角色"。

## 1. 叙事弧骨架(用户没有大纲时用它搭)

```
钩子(Hook)      → 1 页   : 反差 / 问题 / 硬数据,让人停下来
定调(Context)   → 1-2 页 : 背景 / 你是谁 / 为什么讲这个
主体(Core)      → 3-5 页 : 核心内容,用 layouts.md 的数据/结构/图文版式穿插
转折(Shift)     → 1 页   : 打破预期 / 提出新观点
收束(Takeaway)  → 1-2 页 : 金句 / 行动建议 / 联系方式
```

页数规划:15 分钟 ≈ 10 页,30 分钟 ≈ 20 页,45 分钟 ≈ 25-30 页。总建议时长不超过用户时长的 90%,留停顿与意外缓冲。

## 2. 受众与目标(一页一观点的前提)

动手前确认(一次问清,最多 3 问):

| 要问                                        | 为什么                      |
| ------------------------------------------- | --------------------------- |
| 受众与场合(内部分享 / 发布会 / 汇报 / 教学) | 决定语言风格与信息密度      |
| 时长                                        | 决定页数                    |
| 有无原始素材(文档/数据/旧 PPT)              | 有素材就基于素材,没有就帮搭 |
| 硬约束(必含数据 / 禁出现内容)               | 避免返工                    |

目标类型映射:

| 场合       | 结构                                         |
| ---------- | -------------------------------------------- |
| 汇报同步   | 背景 → 进展 → 关键决策 → 下一步 → 需要的支持 |
| 评审求反馈 | 目标 → 方案走查 → 理由 → 开放问题 → 请反馈   |
| 发布/展示  | 问题 → 过程 → 方案 → 证据 → 影响 → 下一步    |

## 3. 三表对齐后才动手

写代码前产出三张表,对齐后进模板填充:

1. **页面计划**:页码 → 页面角色(叙事弧) → 内容要点
2. **版式计划**:页码 → data-layout(layouts.md 编号) → 选用理由 → 图片槽位
3. **主题节奏表**:页码 → `light` / `dark` / `accent` / `hero dark` / `hero light`

## 4. 主题节奏硬规则

- 每页 section 必须带 `light` / `dark` / `accent` 之一(hero 页写 `hero dark` 等,默认 light 可省略)
- 连续 3 页以上同主题 = 视觉疲劳,不允许
- 8 页以上必须有 ≥1 个 dark 正文页制造呼吸
- 每 3-4 页插入 1 个 hero 页(封面 / 幕封 / 大引用 / 大字报)
- hero 与非 hero 交替:连续 2 页以上 hero 累,连续 4 页以上 non-hero 死

## 5. 演讲备注(正式演讲时)

每页 `<section>` 写唯一稳定的 `data-slide-id`,并按同序生成 `SPEAKER_NOTES` 记录(模板底部数组):

```js
{ id:"hook", title:"开场", purpose:"让观众停在问题上",
  talk:"补充背景、例子、判断依据;不逐字复述 slide 上的字",
  transition:"为什么下一页紧接着出现", minutes:"2" }
```

- slide 只放观众此刻必须看见的结论、结构和证据;背景与语气进 `talk`
- 备注数量、顺序、id 必须与页面一致(validate_deck.py 会拦)
- 用户没提供的现场信息不猜:时长缺失显示横杠,可选字段整段省略

## 6. 图片约定(有图时先说清)

- 位置:与 index.html 同级 `images/`;命名 `{页号}-{语义}.{ext}`(如 `01-cover.jpg`)
- 规格:单张 ≥1600px 宽;照片用 JPG、透明 UI 用 PNG;整 deck ≤10MB
- 比例只用标准档:16:9 / 16:10 / 4:3 / 3:2 / 1:1;网格内多图统一比例与高度
- 替换保持同名覆盖;没图先用占位色块出结构,图文页无图不能视觉验证(告知用户)
- 配图生成走 wudaozi skill(文生图),比例按本节标准;
- 论文级架构/机制插图(Figure 1/系统图/流程图):调用 figgenie-paper-diagram skill 生成出版级 SVG,嵌入方式 = `<svg>` 内联(viewBox 等比缩放)或存 images/ 引用;生成图是素材不是页面:图内不要自带页眉 / 页码 / 标题 / 边框
